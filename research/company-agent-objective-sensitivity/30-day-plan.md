# 30-day execution plan with kill and pivot gates

Day 0 is 2026-07-23. The immediate workshop target is Aug 29 AoE.

## Days 1–5 — construct validity and replication

- Freeze preregistration V1, objective ontology, action taxonomy, and hidden
  stakeholder utility.
- Reproduce the current synthetic pilot from a clean checkout.
- Inspect CoffeeBench code/data/license and reproduce its profit→revenue stress
  test without changing its benchmark.
- Recruit two domain reviewers for transition and outcome calibration.

**Kill K1:** If CoffeeBench already exposes a complete paired multi-objective audit,
drop the “new benchmark” claim and submit a replication/measurement note.

## Days 6–10 — environment and evaluator hardening

- Add cash/runway only as an extension registered before model data.
- Create semantic paraphrase families and normalized target-intensity levels.
- Build hidden-outcome and exploit fixtures; separate process and state graders.
- Run oracle, passive, rules, random, and deliberate-gaming controls.

**Pivot P1:** If oracle rankings or outcomes are unstable across seeds, pivot from
agent comparison to simulator/evaluator validity.

## Days 11–15 — no/low-cost model calibration

- Select one open-weight and one API family, freeze harness/version/temperature.
- Estimate paid API cost from exact episodes, turns, tokens, retry cap, and current
  provider prices; request approval before spending.
- Run a small disjoint calibration set to estimate variance and invalid-run rate.
- Conduct simulation-based power analysis.

**Kill K2:** If the minimum design cannot distinguish OCAD +0.15 or a 10-point
violation-risk difference within the approved budget, do not run confirmatory
models; redesign or narrow.

## Days 16–21 — confirmatory execution

- Freeze code/data hashes and condition order.
- Run 12 common seeds x 3 repeats x 3 objectives x 2+ families.
- Preserve all failures and model/tool receipts.
- Blind and independently grade trajectory mechanisms.

**Pivot P2:** If objective effects disappear under paraphrase controls, write a
prompt-framing sensitivity paper rather than an objective-sensitivity paper.

## Days 22–25 — analysis and red team

- Recompute state outcomes and primary endpoint from raw episodes.
- Report paired intervals, mixed-effects estimates, seed plots, invalid rates,
  grader agreement, and negative results.
- Run novelty and experimental-validity reviews on the frozen paper/evidence.

**Kill K3:** If grader agreement is below 0.67 or hidden utility is trivially
gameable, block behavioral headline claims.

## Days 26–30 — paper and release

- Revise the 4–9 page workshop paper and anonymized artifact.
- Run claim-ledger, license, privacy, secret, determinism, and clean-build checks.
- Recheck the exact workshop CFP and submit before Aug 29 AoE only with author
  approval.
- Start ICLR 2027 full-paper backlog; do not invent unannounced deadlines.

**Go G:** Submit benchmark claim only if paired effects replicate across at least
two objective paraphrases and two environments or clearly label the second
environment as pending in a design/workshop paper.

## Parallel business-synergy track

Interview potential evaluator users about decision usefulness, not “would you buy
AI data?” Record whether objective-response signatures change a deployment or
procurement decision. Keep buyer evidence separate from scientific validity and
do not ingest private operating records into the benchmark.
