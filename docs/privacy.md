# Privacy and threat model

Howlong is designed for locally sensitive agent transcripts. The primary
security property is not “redacted transcript viewing”; it is that transcript
content never becomes a product output at all.

## Protected data

- prompts and queued commands;
- assistant response and reasoning text;
- tool arguments, command text, results, errors, and attachments;
- file and project paths;
- source filenames;
- provider session, message, request, and tool-call identifiers.

## Allowed metadata

- provider;
- source and turn ordinal generated by Howlong;
- timestamps and elapsed duration;
- completion status/evidence;
- model identifier from an approved provider field;
- token counters;
- static warning codes and aggregate skipped-record counts.

## Processing boundary

1. The browser receives a `File` only after explicit user selection or drop.
2. A dedicated Worker reads the source.
3. Provider adapters access only documented metadata paths.
4. The Worker returns normalized allowlisted objects.
5. React renders those objects and the export serializer maps them through a
   second explicit allowlist.

The main thread never receives raw session records.

For OpenCode export JSON, message `parts` and non-allowlisted session/message
fields are never copied into normalized objects. For SQLite, `json_extract()`
reads approved fields inside the database engine. `message.data`,
`session_message.data`, and `part.data` are not returned to JavaScript.

The file input is cleared as soon as its `File` objects are handed to the
Worker. After each result, the Worker is terminated; choosing “Clear” creates
a fresh prewarmed Worker for the next analysis. This reduces the lifetime of
raw strings and SQLite memory without making a post-analysis network request.

## Network and persistence

The application ships all code, Worker JavaScript, and SQLite WASM locally.
The Worker and WASM are prewarmed before file selection.
After prewarming, Worker fetch, WebSocket, EventSource, XMLHttpRequest, and
dynamic script loading APIs are replaced with fail-closed stubs.

Playwright switches the browser offline after the ready signal and verifies that
analysis and export still complete with zero requests. It also checks:

- zero WebSockets;
- service workers blocked;
- zero cookies;
- empty localStorage and sessionStorage;
- no IndexedDB database;
- no Cache Storage entry;
- no OPFS entry.

The CSP allows same-origin connection only because browser WASM initialization
uses a same-origin fetch before analysis:

```text
default-src 'self';
script-src 'self' 'wasm-unsafe-eval';
worker-src 'self';
connect-src 'self';
style-src 'self';
font-src 'self';
img-src 'self';
object-src 'none';
base-uri 'none';
form-action 'none'
```

No third-party origin is permitted or referenced.

The Vite development and preview servers also emit CSP with
`frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, COOP, CORP, and a
no-referrer policy. Equivalent response headers should be configured on any
static production host; the document-level CSP remains a fallback.

## Untrusted input handling

- Format detection uses magic bytes and structural fields.
- JSON parse errors are counted, not reflected.
- Individual JSONL records over 8 MiB are skipped before provider detection
  calls `JSON.parse`; detection is bounded to 80 inspected records, and lines
  are iterated without splitting the entire file into an array.
- Model labels are length-limited, whitespace-free, and restricted to a
  conservative ASCII identifier character set.
- File, combined byte, per-source run, and combined run limits bound what can
  cross from the Worker to the UI.
- React text nodes are used for rendering; no `innerHTML` exists.
- The app does not evaluate source code or dynamically import source-provided
  paths.
- SQLite opens read-only after an integrity check. The serialized image is
  copied into SQLite-owned memory with zero padding, and its documented
  free-on-close ownership contract is followed on success and failure.
- Unsupported or corrupt files produce static fail-closed results.

## Privacy verification

Every synthetic fixture embeds the canary
`TURNSPAN_PRIVATE_CANARY_7f3b` in private content fields.

Tests assert the canary is absent from:

- parser and merged result serialization;
- metadata JSON export;
- visible and hidden DOM;
- ARIA snapshot;
- browser console;
- download bytes.

Tests also assert that fixture filenames are absent from the DOM.

## Non-goals and honest limits

- JavaScript cannot promise cryptographic secure erasure of memory. Clear
  terminates the Worker and drops references, but Howlong does not claim secure
  RAM wiping.
- A malicious browser extension, compromised browser, or compromised operating
  system is outside the threat model.
- Browser crash dumps and OS swap are controlled by the browser/OS, not
  Howlong.
- OpenCode WAL frames cannot be reconstructed from a lone main database file.
- A model identifier is metadata the user explicitly asked to analyze; it is
  still treated as untrusted input and constrained before output.
